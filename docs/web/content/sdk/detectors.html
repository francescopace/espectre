How one second of CSI becomes a decision

Wi-Fi CSIpacket supply
10 ms slotsone sample per slot
Frequency viewsselected tones and subbands
Featuresone-second window
Motion stateruntime event

The detector targets 100 admitted samples per second. Each packet enters a 10 ms time slot, but only the packet nearest the slot center is retained. Missing slots remain missing, and a burst inside one slot still contributes one sample. Packet bursts therefore cannot make detector time advance faster than elapsed time.

A decision window covers one second and becomes ready at 70% slot occupancy. The runtime evaluates it every 250 ms. A gap resets temporal state instead of joining unrelated periods.

Packet rate supplies the time grid; it is not extra evidence. More packets can fill missing slots, but multiple packets inside one occupied slot do not add detector time.

Frequency inputs follow the feature

Both profiles track twelve fixed tones distributed across the usable HT20 band for temporal turbulence: ±4, ±9, ±14, ±19, ±24, ±28 in centered coordinates. The fixed geometry keeps every session comparable and avoids room-specific subcarrier selection.

High Accuracy therefore uses more than the twelve-tone path. It retains a normalized view of the full live band for channel-shape features, while the temporal trackers remain small. Ratios, correlations, crossing rates, and normalized geometry limit sensitivity to absolute receive gain while AGC remains enabled.

Why the High Accuracy model stays small

The classifier does not consume raw CSI. Time admission has restored a physical-time axis, and the eight inputs already describe normalized motion and channel-shape behavior. The current export contains 492 connection weights and 37 biases: 529 parameters, or 2,116 bytes as 32-bit floats. The C++ detector evaluates those arrays directly without a separate neural-network runtime.

The parameter count describes the current production export. It is not a compatibility promise about future model topology.

Select the profile before setup

The full runtime then owns time admission, evaluation cadence, readiness, gap reset, and hit filtering.

espectre::RuntimeConfig config =
    espectre::make_runtime_sensing_config_from_kconfig();
config.detection_algorithm =
    espectre::DetectionAlgorithm::HIGH_ACCURACY;

espectre::RuntimeFrontendController runtime;
runtime.set_config(config);
runtime.setup(listener);

Use DetectionAlgorithm::LIGHTWEIGHT for the lower-cost profile. A core-only integration may instantiate detector classes directly, but it must reproduce the runtime's timing, readiness, gap-reset, and hit-filter contracts.
