Run the Wi-Fi motion detection example

Create a complete ESP-IDF project from the registry, configure Wi-Fi, and log motion events on your board. Then use its runtime adapter in your own firmware.

Create, build, and flash

Activate ESP-IDF 5.5.5. Choose an exact tagged release, including a release candidate, from production, and replace VERSION_FROM_REGISTRY below. For a branch snapshot from staging, change the URL to https://components-staging.espressif.com. Older prereleases published under the previous policy remain on staging.

ESPECTRE_VERSION="VERSION_FROM_REGISTRY"
ESPECTRE_REGISTRY_URL="https://components.espressif.com"
idf.py create-project-from-example --registry-url "$ESPECTRE_REGISTRY_URL" "francescopace/espectre=$ESPECTRE_VERSION:wifi_motion_detection"
cd wifi_motion_detection

The packaged example pins its SDK version and registry in main/idf_component.yml. For an older staging example with only a version, add registry_url: https://components-staging.espressif.com under francescopace/espectre before configuring or building it.

Choose your board's target and serial port. Set your SSID and password under ESPectre example in menuconfig. Keep credentials in the local project configuration.

idf.py set-target esp32c3
idf.py menuconfig
idf.py build
idf.py -p YOUR_PORT flash monitor

The example enables CSI, initializes Wi-Fi and logging, and reports motion when calibration is ready. See its README for lifecycle and hardware checks, and the SDK installation guide for registry channels.

Add sensing to your application

For an existing project, use idf.py add-dependency as shown in the installation guide. Component Manager maintains the SDK under managed_components/. Keep your runtime adapter in the application component:

product-firmware/
├── managed_components/
│   └── francescopace__espectre/
└── main/
    ├── CMakeLists.txt
    ├── idf_component.yml
    ├── main.cpp
    └── product_frontend.h

The manifest declares the SDK dependency. Register your application's sources in CMake:

# main/CMakeLists.txt
idf_component_register(
  SRCS "main.cpp"
  INCLUDE_DIRS "."
)

For manual vendoring, source archives remain available on the SDK page. Follow the build integration instructions for that layout.

Choose the logging backend

The shared SDK has no default logger and does not require ESP-IDF's log component. If the product needs shared messages, register a complete sink before runtime setup:

espectre::LogSink sink{
    product_log_context,
    &product_log_enabled,
    &product_log_write,
};
if (!espectre::set_log_sink(sink)) return false;

The enabled callback receives the level and tag before message arguments are evaluated. The write callback receives the source line, format string, and a bounded-lifetime va_list. Keep both callbacks thread-safe, non-blocking, and non-reentrant, and clear the sink only after runtime shutdown.

Own the runtime from one task

This adapter uses menuconfig-backed sensing defaults, gates product output on readiness, and keeps publication outside the listener callback:

#include "espectre_sdk.h"

class ProductFrontend : public espectre::IRuntimeListener {
 public:
  bool setup() {
    runtime_.set_config(
        espectre::make_runtime_sensing_config_from_kconfig());
    return runtime_.setup(this);
  }

  void loop() {
    runtime_.loop();
    if (!motion_changed_) return;
    motion_changed_ = false;
    publish_motion(latest_motion_);  // product-owned, may queue more work
  }

  void shutdown() { runtime_.shutdown(); }

  void on_motion_state_changed(
      const espectre::RuntimeSnapshot& snapshot) override {
    if (!snapshot.ready_to_publish) return;
    latest_motion_ =
        snapshot.motion_state == espectre::MotionState::MOTION;
    motion_changed_ = true;
  }

  void on_runtime_fault(const char* message) override {
    record_runtime_fault(message);  // copy if retained after this call
  }

 private:
  void publish_motion(bool motion);
  void record_runtime_fault(const char* message);
  espectre::RuntimeFrontendController runtime_;
  bool latest_motion_{false};
  bool motion_changed_{false};
};
The placeholder functions belong to the product. publish_motion() should hand potentially blocking I/O to another task. record_runtime_fault() must copy the message if it retains it because the pointer is valid only during the callback.

Handle startup, steady state, and shutdown

  1. Create the station before setup

    Call setup after the default station and event loop exist. Prefer setup before association so the CSI radio policy is applied at station start; if the product is already connected, the runtime restores the current IPv4 state.

  2. Check the setup result

    A failed setup() leaves the controller un-setup. Correct the configuration or link state before retrying.

  3. Call loop continuously

    loop() drains deferred CSI work and delivers listener events. Slow product callbacks can fill the bounded mailbox and drop incoming frames.

  4. Shut down from the owner task

    Call shutdown() before tearing down Wi-Fi or the application services used by the adapter.

Choose a reference frontend

ESPHome, Native, and Matter use the same public SDK headers as external integrators. Their source lists are separate from the SDK source groups. Use these frontends as implementation references and depend on the public SDK API in your own firmware.

To build a reference frontend against an extracted SDK bundle, set ESPECTRE_SDK_ROOT to the absolute path of its src/cpp directory. ESPHome checks its generated sensing schema against the selected SDK before compilation. See CLI.md for build commands, including Native and Matter Docker builds.
