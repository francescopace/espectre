Integrate a product frontend

Start with the smallest supported runtime adapter, then inspect the shipped frontend whose lifecycle and product boundary most closely match your firmware.

Minimal ESP-IDF component

Extract the release bundle, then vendor the bundle's src/cpp/ directory as components/espectre/. Keep the product adapter in your application component so it can use product-owned services without adding upward dependencies to the SDK.

product-firmware/
├── components/
│   └── espectre/          # contents of the bundle's src/cpp directory
└── main/
    ├── CMakeLists.txt
    ├── main.cpp
    └── product_frontend.h

Declare the component dependency from the application:

# main/CMakeLists.txt
idf_component_register(
  SRCS "main.cpp"
  INCLUDE_DIRS "."
  REQUIRES espectre
)

Own the runtime from one task

This adapter uses menuconfig-backed sensing defaults, gates product output on readiness, and keeps publication outside the listener callback:

#include "espectre_sdk.h"

class ProductFrontend : public espectre::IRuntimeListener {
 public:
  bool setup() {
    runtime_.set_config(
        espectre::make_runtime_sensing_config_from_kconfig());
    return runtime_.setup(this);
  }

  void loop() {
    runtime_.loop();
    if (!motion_changed_) return;
    motion_changed_ = false;
    publish_motion(latest_motion_);  // product-owned, may queue more work
  }

  void shutdown() { runtime_.shutdown(); }

  void on_motion_state_changed(
      const espectre::RuntimeSnapshot& snapshot) override {
    if (!snapshot.ready_to_publish) return;
    latest_motion_ =
        snapshot.motion_state == espectre::MotionState::MOTION;
    motion_changed_ = true;
  }

  void on_runtime_fault(const char* message) override {
    record_runtime_fault(message);  // copy if retained after this call
  }

 private:
  void publish_motion(bool motion);
  void record_runtime_fault(const char* message);
  espectre::RuntimeFrontendController runtime_;
  bool latest_motion_{false};
  bool motion_changed_{false};
};
The placeholder functions belong to the product. publish_motion() should hand potentially blocking I/O to another task. record_runtime_fault() must copy the message if it retains it because the pointer is valid only during the callback.

Handle startup, steady state, and shutdown

  1. Create the station before setup

    Call setup after the default station and event loop exist. Prefer setup before association so the CSI radio policy is applied at station start; if the product is already connected, the runtime restores the current IPv4 state.

  2. Check the setup result

    A failed setup() leaves the controller un-setup. Correct the configuration or link state before retrying.

  3. Call loop continuously

    loop() drains deferred CSI work and delivers listener events. Slow product callbacks can fill the bounded mailbox and drop incoming frames.

  4. Shut down from the owner task

    Call shutdown() before tearing down Wi-Fi or the application services used by the adapter.
