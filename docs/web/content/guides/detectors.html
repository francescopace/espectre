DETECTION PROFILES · 7 MIN READ

Choose your detection profile

Choose Lightweight when sensing must leave resources for the rest of the device. Choose High Accuracy when detection quality and cross-environment generalization matter more.

RESOURCE HEADROOM

Lightweight Detection

Uses fewer feature trackers, less working memory, and less per-packet computation. It adapts its threshold to the room during a quiet startup calibration of up to about ten seconds.

lightweight

DETECTION QUALITY

High-Accuracy Detection

Uses additional feature state and a compact neural network for stronger accuracy and generalization on the maintained corpus. It does not need quiet-room threshold calibration.

high_accuracy

The practical difference

Product concernLightweightHigh Accuracy
Active runtime costLower CPU and working-memory useMore feature state and neural-inference work
Detection qualityGood production baseline, with less cross-environment robustnessHigher accuracy and stronger generalization on the maintained corpus
StartupUp to about ten seconds of quiet threshold calibrationNo threshold calibration; waits for CSI and feature-window readiness
Training dependencyNo training data neededShips with an open, pre-trained model
Typical fitConstrained devices or firmware reserving resources for other servicesProducts that prioritize detection quality and can afford the additional runtime cost
These are resource profiles, not power modes. The project benchmarks detector CPU and memory separately; it does not claim that selecting a profile produces a measured whole-device energy saving. If both implementations are compiled into one image, Lightweight can reduce active detector work without removing the High Accuracy model and weights from flash.

Choose in thirty seconds

  • Choose Lightweight when sensing shares a smaller chip with displays, connectivity, Matter, OTA, or other application services.
  • Choose High Accuracy when false-positive control, transfer across rooms, and detection quality are the priority.
  • Start with Lightweight when you are unsure, then compare High Accuracy in the installed room if your frontend supports runtime switching.
  • Validate inside the complete product: placement, packet flow, CPU load, memory headroom, and the surrounding firmware all affect the final choice.

Startup is different

Lightweight observes a quiet room and adapts its threshold to the current session. Keep the room still after boot or when recalibrating, and recalibrate after moving the sensor to a substantially different position.

High Accuracy uses the threshold validated with its trained model, so it skips quiet-room threshold calibration. It is not instant: CSI capture still has to become ready, and the feature window still has to fill before detection starts.

Consumer and OEM controls

Published ESPHome and Native firmware include both profiles, can switch at runtime, and persist the selection. Matter supports both as build-time choices, publishes Lightweight by default, and does not currently expose a runtime profile control.

For ESPHome configuration:

espectre:
  detection_algorithm: lightweight  # or high_accuracy

For an SDK integration:

espectre::RuntimeConfig config;
config.detection_algorithm = espectre::DetectionAlgorithm::HIGH_ACCURACY;

For the shared MQTT command:

{"command":"set_detector","detector":"high_accuracy"}
