Built-in or ESPectre component

The built-in component and the ESPectre ESPHome component run the same SDK. They differ in what comes around it. This guide covers ESPHome 2026.11.

Start with the built-in component when you already maintain an ESPHome configuration and want motion as one more entity. Use the ESPectre component or an official image for the browser tools.

Your first configuration

Add the hub and a motion sensor to a configuration that already sets up Wi-Fi:

espectre:

binary_sensor:
  - platform: espectre
    motion:
      name: Motion

The sensor calibrates after each connection, while the room is quiet. Keep the room still for the first half minute after the device joins Wi-Fi.

Options

All options go under espectre: and are optional. The defaults suit most rooms.

Options of the espectre component
OptionValues
detection_algorithmlightweight (default) or high_accuracy. See detection profiles.
traffic_generator_modeping (default), dns, dns_tcp, wifi_raw, or external. wifi_raw is not available on ESP32-C6.
traffic_generator_target_ipA unicast IPv4 address for ping, dns, or dns_tcp traffic, instead of the gateway
traffic_generator_target_macA unicast MAC address for wifi_raw traffic, such as another ESPectre device
csi_traffic_multicast_groupThe multicast group of an external traffic source, with external mode
motion_on_hits, motion_off_hitsHow many detections in a row turn motion on or off, from 1 to 20
csi_target_ppsCSI packets per second to aim for, from 1 to 500
csi_sample_spacinghalf_slot (default) or distinct. On a busy channel, distinct keeps packets that arrive in back-to-back pairs.
window_size, evaluation_intervalThe detection window, from 1 to 2 seconds, and how often it is evaluated, from 10 ms to 10 s
lowpass_filter, hampel_filterSignal filters, each with enabled. The low-pass filter takes a cutoff from 5 to 20 Hz; the Hampel filter takes a window from 3 to 11 and a threshold from 1 to 10.
csi_capture_profileauto (default), lltf, or ht_vht. Leave it on auto unless you are testing.

Entities

The component creates only the entities you list. This configuration adds the ones most people want:

binary_sensor:
  - platform: espectre
    motion:
      name: Motion
    calibrating:
      name: Calibrating

sensor:
  - platform: espectre
    movement:
      name: Movement
    diagnostics:
      update_interval: 10s
      csi_accepted_rate:
        name: CSI Accepted Rate
      csi_occupancy:
        name: CSI Temporal Occupancy

number:
  - platform: espectre
    threshold:
      name: Threshold

select:
  - platform: espectre
    detection_algorithm:
      name: Detection Algorithm
    traffic_generator_mode:
      name: Traffic Mode

switch:
  - platform: espectre
    sensing:
      name: Sensing

button:
  - platform: espectre
    name: Recalibrate
  • Controls apply at runtime, without a new build. Numbers also cover motion_on_hits and motion_off_hits, and the selects also cover csi_sample_spacing. The Sensing switch pauses sensing and is restored after a reboot.
  • Diagnostics also include generator_rate, traffic_tx_rate, traffic_rx_rate, csi_callback_rate, csi_missing_slot_rate, and csi_excess_rate. They publish nothing until you set update_interval or call component.update on them.
  • The traffic generator app fills its panel from these entities when they use the names it expects. See the Home Assistant guide.

What the component changes in ESPHome

CSI needs a steady stream of received packets, so the component adjusts the radio:

  • Wi-Fi power save is always off, also while the device is disconnected.
  • ESPHome's periodic roaming scans stop, because each one interrupts sensing. Losing the access point still triggers a normal reconnect.
  • Wi-Fi aggregation is off in both directions, because CSI needs one report per frame. This can lower Wi-Fi throughput for the whole firmware.
  • It needs ESP-IDF 5.5.3 or later, or Arduino 3.3.7 or later, on ESP32, ESP32-S2, ESP32-S3, ESP32-C3, ESP32-C5, or ESP32-C6.

Current limits

  • No Direct API yet, so Monitor, Device settings, Find devices, and the ./espectre device commands cannot reach the board. Home Assistant covers the same checks through the entities: watch Movement against Threshold, the calibration state, and the traffic and CSI diagnostics, and tune the controls from there.
  • Raw CSI collection for datasets needs the Direct API, so it is not available either.

For every option and platform, see the ESPHome documentation.
