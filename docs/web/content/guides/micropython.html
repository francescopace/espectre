ESPectre brought ESP32 CSI to mainline MicroPython

ESPectre contributed direct Wi-Fi Channel State Information access to MicroPython through micropython/micropython#18460. The merged ESP32 network.WLAN methods expose CSI capture, buffered reads, availability, and dropped-frame diagnostics from Python.

Micro-ESPectre now builds a pinned mainline MicroPython revision with a lean ESPectre board profile rather than using the historical CSI fork. The contribution was merged into mainline for the MicroPython 1.29.0 release cycle, so other MicroPython projects can use the same ESP32 CSI interface.

The durable claim is the contribution itself: ESPectre added direct ESP32 CSI access to mainline MicroPython, and then built an on-device sensing runtime on top of it.

What runs on the ESP32

Micro-ESPectre is not a desktop Python backend. CSI capture, temporal admission, feature extraction, detection, motion-state filtering, traffic generation, and telemetry all run on the microcontroller. Normal operation publishes derived motion state and movement score; raw CSI is reserved for explicit research and collection workflows.

CLI workflow

The repository wrapper builds and flashes the matching project image, then deploys and verifies the Micro-ESPectre application.

  1. Prepare the repository environment

    Create the project virtual environment and install the base requirements.

  2. Build and flash the project image

    Select the target chip. The wrapper builds the matching pinned MicroPython revision and native components, then installs the canonical project image over USB.

  3. Deploy and run Micro-ESPectre

    Create the local configuration from the provided example, then copy the runtime to the device and start it.

python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

cp src/python/micro_espectre/config_local.py.example \
  src/python/micro_espectre/config_local.py

./espectre micro flash --chip c3 --erase
./espectre micro deploy
./espectre micro verify
./espectre micro run
Keep Wi-Fi credentials in config_local.py. Never commit that local file.

Lightweight sensing

The deployed runtime contains only the Lightweight detector. It adapts its threshold from clean, ready quiet-room coverage during startup. High Accuracy sources and weights remain in the repository for research and parity validation, but micro deploy does not copy them to the device.

Micro-ESPectre exposes the health, device, capabilities, sensing, wifi, and diagnostics resources through Direct HTTP. Its events stream publishes resource updates, motion evaluations, and faults. A one-second serial heartbeat reports sensing status. It has no MQTT, CSI collection stream, device discovery resource, or Home Assistant adapter.

Current role and limits

Micro-ESPectre is ESPectre's maintained Python and MicroPython experimentation path. It is not yet presented as a stable embeddable SDK: the current distribution deploys the complete reference runtime, and its supported public library boundary has not been frozen.

  • The deployed detector is fixed to Lightweight.
  • The Direct surface is read-only; configuration changes require a filesystem deployment.
  • Bluetooth provisioning and OTA are not implemented on the MicroPython path.
  • Production changes still require aligned C++ behavior and parity validation.

For configuration, Direct endpoints, implementation detail, and development checks, continue with the maintained Micro-ESPectre reference.
