Examples

The real SDK examples are the frontends already shipped in this repository. Start from the closest one, then strip away the parts your product does not need.

Custom frontend over the shared runtime

Most products should start here: keep your own app shell, networking policy, storage, and UI, then forward runtime events into product behavior.

bool ProductFrontend::setup() {
  runtime_.set_config(config_);
  return runtime_.setup(this);
}

void ProductFrontend::on_motion_state_changed(const espectre::RuntimeSnapshot& snapshot) {
  runtime_.record_snapshot(snapshot);
  if (!snapshot.ready_to_publish) return;
  publish_motion(snapshot.motion_state, snapshot.movement_metric);
}

Reference pattern: the shared controller usage in the Native, Matter, and Streamer frontends.

Native BLE and MQTT device

The Native frontend is the reference when you need product-controlled provisioning, a lightweight BLE control surface, MQTT telemetry, or HTTPS OTA. It shows how to bridge runtime events into both push telemetry and command handling without changing the sensing layers.

void on_periodic_update(const espectre::RuntimeSnapshot& snapshot, uint32_t packets_received) override {
  runtime_.record_snapshot(snapshot);
  if (!snapshot.ready_to_publish) return;
  publish_mqtt_telemetry(snapshot, now_ms());
  log_status(snapshot, packets_received);
}

Reference: src/cpp/frontend/native/ plus ESPECTRE_PROTOCOL.md.

Matter occupancy sensor

The Matter frontend shows the smallest ecosystem mapping: take the shared motion state, wait until the runtime is ready, and publish it into the standard occupancy cluster.

void on_motion_state_changed(const espectre::RuntimeSnapshot& snapshot) override {
  runtime_.record_snapshot(snapshot);
  if (!snapshot.ready_to_publish) return;
  bindings_->publish_motion(endpoint_id_, snapshot_to_motion_detected(snapshot));
}

Reference: src/cpp/frontend/matter/.

Core-only experiments and custom capture

If your firmware already owns Wi-Fi and CSI capture, you can reuse only the detector layer. This is the lightest path, but it also means you own frame normalization, evaluation cadence, readiness gating, and hit filtering. Use the shared pipeline as the reference before diverging.

Reference: runtime/esp_idf/csi_pipeline.cpp, the Streamer frontend in src/cpp/frontend/streamer/, and the ML training workflow.
