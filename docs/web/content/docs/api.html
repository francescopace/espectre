The four types to know

RuntimeFrontendController Owns setup, the work loop, shutdown, cached state, and validated runtime controls. RuntimeConfig Defines detector, traffic, cadence, filtering, and other startup settings. IRuntimeListener Delivers motion, periodic status, calibration, telemetry, and fault events. RuntimeSnapshot Carries motion state, movement score, threshold, link state, and readiness.
Treat the detector as a product-budget choice. Classic uses less active CPU and working memory but is less accurate; ML improves accuracy and generalization with additional feature state and inference work. Classic calibrates for up to about 10 seconds at startup, while ML skips threshold calibration and waits only for CSI readiness and feature-window warmup.

Replacing the runtime

A platform port implements IEspectreRuntime. The interface covers lifecycle, state, controls, diagnostics, capabilities, and listener delivery; the existing RuntimeFrontendController remains ESP-IDF-specific and does not inject an arbitrary backend.
