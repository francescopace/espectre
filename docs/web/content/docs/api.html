SDK · API

API reference

The embedding surface is the shared runtime contract, not a single Sensor class. Most firmware integrations include espectre_sdk.h, reuse RuntimeFrontendController, implement IRuntimeListener, and feed product behavior from RuntimeSnapshot.

Recommended integration surface

#include "espectre_sdk.h"

class ProductFrontend : public espectre::IRuntimeListener {
 public:
  bool setup() {
    espectre::RuntimeConfig config;
    runtime_.set_config(config);
    return runtime_.setup(this);
  }

  void loop() { runtime_.loop(); }
  void shutdown() { runtime_.shutdown(); }

  void on_motion_state_changed(const espectre::RuntimeSnapshot& snapshot) override {
    runtime_.record_snapshot(snapshot);
    if (!snapshot.ready_to_publish) return;
    publish_motion(snapshot.motion_state, snapshot.movement_metric);
  }

 private:
  espectre::RuntimeFrontendController runtime_;
};
Type or methodWhat it does
RuntimeFrontendController::set_config()Stores the runtime configuration before setup, including detector choice, publish cadence, thresholds, hit-filter counts, and traffic settings.
RuntimeFrontendController::setup(listener)Creates the runtime backend, applies the config, captures the initial snapshot and capabilities, and starts the sensing path.
RuntimeFrontendController::loop()Runs the runtime work loop. Frontends call this from their main loop or task.
RuntimeFrontendController::shutdown()Stops the sensing runtime cleanly.
RuntimeFrontendController::snapshot()Returns the latest cached RuntimeSnapshot for status, UI, or protocol serialization.
RuntimeFrontendController::capabilities()Returns the discovered runtime capabilities so frontends can expose only supported controls.
Three rules cover most integration mistakes. Gate everything user-visible on snapshot.ready_to_publish, because the runtime emits snapshots while it calibrates. Run setup(), loop(), and shutdown() on one task. Ask capabilities() before exposing a control instead of assuming the active runtime supports it.

Threading contract

The runtime carries no internal locking, and every IRuntimeListener callback is delivered on the caller's task: from loop() for sensing events, or inline on the task that invoked a control method. Work raised in the Wi-Fi CSI callback is deferred through an internal mailbox first, so no listener callback runs in interrupt or Wi-Fi driver context. Because callbacks run on your own task, blocking in them is allowed: publishing over MQTT or writing NVS costs loop latency, not CSI frames.

The transport seams follow their own stack instead. IOtaService callbacks arrive on the OTA worker task, and IBleBindings callbacks on the BLE host task; each header states its own contract.

CallbackWhen to use it
on_motion_state_changed()Edge-triggered motion updates after the hit filter. This is the hook Matter uses for occupancy publishing.
on_periodic_update()Heartbeat-style updates with the current snapshot and packet count. Native uses it for periodic telemetry and status logging.
on_threshold_changed() / on_detector_changed()React to runtime control changes and refresh any frontend-facing state.
on_calibration_started() / on_calibration_finished()Show readiness and reset any frontend-side progress or status indicators.
on_live_telemetry()Consume the high-rate movement stream when the frontend exposes a live channel, such as BLE notifications.
on_runtime_fault()Surface runtime-owned failures into your product logs, diagnostics, or transport.

Snapshot and control surface

MemberMeaning
snapshot.motion_stateThe current debounced state, typically IDLE or MOTION.
snapshot.movement_metricThe current motion-energy score produced by the detector pipeline.
snapshot.thresholdThe active motion threshold on the same scale as movement_metric.
snapshot.calibrating / snapshot.ready_to_publishReadiness flags for startup calibration and safe publication.
snapshot.detector_nameThe active detector label, currently classic or ml when supported.
set_threshold_runtime(float)Updates the threshold at runtime when the active frontend and runtime allow it.
set_detection_algorithm_runtime(DetectionAlgorithm)Switches detector at runtime when capability-gated support is enabled.
trigger_recalibration()Starts a fresh quiet-room baseline calibration.
set_services_armed(bool)Arms or disarms runtime-owned services, which is how the Matter frontend keeps sensing quiet until commissioning completes.
set_live_telemetry_enabled(bool)Toggles high-rate live telemetry without shutting down the runtime.

Build integration

The published SDK bundles package the same source-first integration path documented in this repository. They are intended for vendoring or unpacking into your firmware tree, not as chip-specific binary libraries.

Build pathWhat to include
CMake / ESP-IDFInclude src/cpp/espectre_sources.cmake, then add ESPECTRE_CORE_SOURCES, ESPECTRE_RUNTIME_ESP_IDF_SOURCES, and any needed feature groups such as ESPECTRE_RUNTIME_ESP_IDF_BLE_SOURCES, ESPECTRE_RUNTIME_ESP_IDF_MQTT_SOURCES, ESPECTRE_RUNTIME_ESP_IDF_PROVISIONING_SOURCES, or ESPECTRE_RUNTIME_ESP_IDF_OTA_SOURCES, plus ESPECTRE_SHARED_INCLUDE_DIRS.
PlatformIOReuse the packaged source filter defined in src/cpp/library.json.
ESP-IDF component layoutDrop src/cpp/ into your project's components/ directory and add espectre to your own REQUIRES. The sensing runtime is always built; MQTT, BLE, provisioning, OTA, and the stream runtime are opt-in under the "ESPectre SDK" menuconfig menu.
Core-only reuseConsume the detector layer directly, and use runtime/esp_idf/csi_pipeline.cpp as the normalization and evaluation reference.

ESPECTRE_SHARED_INCLUDE_DIRS puts the SDK root on the include path, so both the flat form (#include "runtime_interface.h") and the layer-prefixed form (#include "runtime/runtime_interface.h") work. Prefer the prefixed form: the shared tree contains generic basenames such as utils.h, and the prefix keeps them from colliding with headers of your own.

Versioning and stability

Everything reachable from espectre_sdk.h is the supported surface and follows the SDK version contract. Every other header ships because the runtime needs it to compile and may change in any release.

IdentifierWhat it versions
ESPECTRE_SDK_VERSION_STRINGThe ESPectre sources you compiled against. Guard code with ESPECTRE_SDK_VERSION_AT_LEAST(major, minor, patch).
espectre_firmware_version()Your application version, supplied by your build system. This is what the protocol reports and what OTA compares against.
ESPECTRE_PROTOCOL_VERSIONThe MQTT and BLE wire format.
