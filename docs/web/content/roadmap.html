Roadmap · A privacy-first sensing layer

Make spaces responsive without making them watch.

ESPectre is building a local-first sensing layer that turns changes already present in Wi-Fi into useful motion events. Processing stays on the device. ESPectre does not collect images or audio, and the default service boundary does not export raw CSI.

Planned · September 2026 v3.0
The first stable foundation

Make the sensing layer dependable and easy to carry into products.

Version 3.0 is planned as the stable baseline for ESPectre as a reusable platform. One shared sensing core supports several firmware paths, so product teams can add local motion sensing without maintaining a separate implementation for each integration.

Shared architecture
The sensing core and shared runtime intended for the stable v3 baseline.

Supported frontends

Release surfaces

PRODUCT DIRECTION

From one node to a shared sensing system.

Each horizon expands what ESPectre can do while keeping the same local-first boundary.

Now · v3.0.0-rc1

Put private sensing inside real products.

The v3 line focuses on the work that makes a sensing component useful outside its own repository: measured quality, documented distribution paths, product integrations, and reliable local operation.

  1. 3.1Improve sensing quality and device-side performance.
  2. 3.2Publish supported ESP-IDF and Arduino SDK distribution paths.
  3. 3.3Establish an evidence-backed Matter and manufacturer-readiness position.
  4. 3.4Add local displays and evaluate cooperative node behavior.
  5. 3.5Promote embedded ecosystem integrations only when a candidate passes its production gates.
Next · v4.x

Let nearby nodes understand a space together.

One detector can describe motion around itself. The planned v4 layer would let several devices appear as one coherent system, while raw CSI and unnecessary radio identifiers remain outside the default service boundary.

  • Claim devices securely, and see rooms, motion state, connectivity, and health.
  • Apply supported settings and signed updates without exporting raw measurements.
  • Choose local, self-hosted, or managed deployment profiles.
Later · v5.x

Carry the same product contract onto better radios.

ESPectre will move only when an embedded platform exposes practical, documented IEEE 802.11bf or equivalent vendor measurements. Existing product integrations should not need a second control plane.

  • Map new measurements into the existing runtime snapshots and events.
  • Measure calibration, false-positive control, and multi-node behavior again.
  • Preserve protocol, frontend, and tooling compatibility.
RESEARCH TRACKS

Some questions still need evidence.

Research does not reserve release scope. A track may become a product, remain a host-side experiment, or end with a measured rejection.

01

5 GHz and new PHYs

Validate HT20 on 5 GHz first, then evaluate VHT20, HE20, and wider layouts with representative detector evidence.

02

Stationary presence

Test whether scale-invariant micro-motion can distinguish an occupied quiet room from an empty one.

03

Brief gestures

Build a gesture-specific corpus only after the high-rate sensing path preserves the necessary short-timescale information.

04

Breathing-related motion

Explore non-medical micro-motion only after stationary presence is measurable and suitable paired recordings exist.

A direction, not a promise.

Priorities can change as hardware support, sensing quality, and product evidence evolve. The maintained project roadmap owns release gates and implementation sequencing.
