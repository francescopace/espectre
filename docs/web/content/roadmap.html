PRODUCT ROADMAP · UPDATED JULY 2026

From motion sensor to sensing platform.

ESPectre is growing around one privacy-first idea: sensing stays local, while the same reusable core can serve homes, embedded products, and optional multi-device orchestration.

A direction, not a promise. Priorities and target dates can change as hardware support, sensing quality, and integration requirements become clearer. Limited validation means the implementation is available, but its ecosystem coverage is not yet mature.
Available Limited validation Planned Research
v3.x · Target August 2026

Modular sensing platform

In progress

The current release line turns ESPectre into a reusable platform with shared sensing logic, multiple firmware frontends, and an SDK-oriented path for custom products.

Available

Home Assistant

The production ESPHome integration remains the simplest route from an ESP32 to local motion automations.

Available

Native, MQTT, and the SDK

Native BLE/MQTT firmware, the CSI streamer, and reusable C++ layers establish the foundation for custom firmware and OEM products.

Available · Limited validation

Matter

The Matter occupancy frontend and published firmware are available. Controller coverage remains limited; broader validation, including SmartThings, Home Assistant Matter, and the Tuya app, is still planned.

Research

Presence and breathing

Research will explore stationary presence and breathing-related micro-motion as distinct local sensing signals. Breathing work is experimental and is not a medical measurement.

Research

Brief gestures

Gesture detection depends on preserving short-timescale information at higher CSI packet rates. It needs its own prototype and validation corpus before becoming a feature.

Evaluation

TuyaOpen and embedded products

A separate TuyaOpen reference integration would embed ESPectre’s shared core and runtime into a TuyaOS product. This is an OEM path, not the same integration as using the Tuya app through Matter.

Evaluation

Zigbee

An ESP32-C6 occupancy frontend is being considered, starting with radio-coexistence measurements between Wi-Fi CSI and 802.15.4.

v4.x · Target December 2026

Optional web orchestration

Planned

Multiple ESPectre nodes should be able to behave like one coherent sensing system without turning raw radio data into a cloud dependency.

Planned

Home map and realtime state

Place devices in rooms, see motion and health at a glance, and explore approximate room-to-room activity without claiming precise localization.

Planned

Onboarding and fleet visibility

Physical-presence pairing, device ownership, firmware status, remote settings, and signed update workflows for multi-device installations.

Planned

History and alerts

Configurable movement history, explicit retention controls, and motion-triggered notifications, beginning with email.

Planned

Local, self-hosted, or managed

The same optional web layer should support local, self-hosted, and managed deployments. Derived telemetry may leave the device when configured; raw CSI does not need to.

v5.x · Future

Standards-ready Wi-Fi sensing

Exploratory

ESPectre will track practical IEEE 802.11bf and vendor-supported Wi-Fi Sensing APIs. When suitable embedded hardware exposes them, the goal is to add another hardware backend while preserving the protocol, tooling, frontends, and product integration model.
