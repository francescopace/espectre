MICROPYTHON RUNTIME

ESPectre also runs sensing directly in MicroPython.

ESPectre contributed direct ESP32 CSI access to mainline MicroPython. Micro-ESPectre uses that upstream foundation for on-device Python experiments, MQTT telemetry, and detector parity work; it remains a maintained R&D runtime rather than a stable embeddable SDK.

DETECTOR BUDGET

Choose accuracy or resource headroom.

Lightweight and High Accuracy are both production profiles. Select between them as part of the product's CPU, memory, startup, and detection-quality budget.

Product concernLightweightHigh Accuracy
Runtime costFewer feature trackers, less working memory, and less per-packet computationMore feature state and neural-inference work
Detection qualityLower accuracy and cross-environment robustnessHigher accuracy and stronger generalization on the maintained corpus
StartupAdapts its threshold during up to about 10 seconds of quiet calibration; may still lower it after a later quiet stretchSkips threshold calibration; starts after CSI is ready and its feature window has filled
Typical fitConstrained chips or firmware that must reserve resources for other product featuresProducts that prioritize detection quality and can afford the additional runtime cost

Set RuntimeConfig::detection_algorithm to DetectionAlgorithm::LIGHTWEIGHT or DetectionAlgorithm::HIGH_ACCURACY before setup. Runtime switching is an optional integration capability; a firmware image that contains both paths may still carry the ML code and weights in flash while Lightweight is active. See the detection profile guide for the complete product decision.

QUICK START

From source bundle to motion events.

Follow these three steps for the recommended full-runtime integration.

01

Add the SDK

Unpack the release source bundle as components/espectre/, then declare the component from your application:

# main/CMakeLists.txt
idf_component_register(
  SRCS "main.cpp"
  REQUIRES espectre
)

The SDK is source-based, so there is no chip-specific library to link. Optional Bluetooth, MQTT, provisioning, OTA, and stream support stay disabled until selected in menuconfig.

02

Drive the runtime

Start it after your station has joined Wi-Fi, call loop() continuously, and react to the events your product needs:

#include "espectre_sdk.h"

class ProductFrontend : public espectre::IRuntimeListener {
 public:
  bool setup() {
    runtime_.set_config(espectre::RuntimeConfig{});
    return runtime_.setup(this);
  }

  void loop() { runtime_.loop(); }

  void on_motion_state_changed(
      const espectre::RuntimeSnapshot& snapshot) override {
    runtime_.record_snapshot(snapshot);
    if (!snapshot.ready_to_publish) return;
    publish_motion(snapshot.motion_state == espectre::MotionState::MOTION);
  }

 private:
  espectre::RuntimeFrontendController runtime_;
};
03

Keep three contracts

  • Publish only when snapshot.ready_to_publish is true.
  • Run setup(), loop(), and shutdown() on one task.
  • Check capabilities() before exposing runtime controls.
