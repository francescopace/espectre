Build a frontend from source

  1. Clone and check the environment

    Clone the repository, create the virtual environment, and run the doctor command: it verifies Python, ESP-IDF, and the serial tooling before your first build. Native, Matter, and Streamer need a working ESP-IDF installation; ESPHome installs its own toolchain.

  2. Build for your chip

    Every frontend builds through the same wrapper; pick the chip explicitly.

  3. Flash and watch the logs

    Each build command has a matching flash/monitor flow; use --help on any subcommand for current options and port naming.

git clone https://github.com/francescopace/espectre.git
cd espectre
./espectre doctor

./espectre esphome build --chip c3
./espectre native build --chip c3
./espectre matter build --chip c3
./espectre streamer build --chip c3 --clean

./espectre native flash --port /dev/cu.usbmodemXXXX
./espectre monitor --port /dev/cu.usbmodemXXXX

Full prerequisites and command reference: SETUP.md and CLI.md.

Streamer credentials are supplied at build time and Streamer binaries are not published by the browser flasher. Never commit local Wi-Fi or MQTT secrets.

Embed ESPectre in an existing firmware

The reusable C++ layers let an ESP-IDF product own boot, networking, storage, OTA, and UI while ESPectre supplies the sensing path. The embedding guide documents the layers, the runtime contracts, and the build integration in detail.

  1. Connect CSI capture

    Feed compatible ESP32 CSI frames into the shared capture and processing boundary, or let the ESPectre runtime own capture entirely.

  2. Select the reusable layers

    Use the core directly for the smallest integration, or reuse the runtime services when you also want lifecycle and orchestration.

  3. Map product events

    Translate movement score, motion state, calibration state, and diagnostics into the product's existing event system.

  4. Validate in context

    Measure CPU, memory, packet flow, reconnect behavior, and detection quality inside the complete product firmware.

ESPectre exposes reusable source layers rather than a precompiled binary SDK, and it is dual-licensed: GPLv3 for open-source firmware, with commercial licenses available for embedding into proprietary products.

Before you ship

  • Build the exact chip and frontend combination you will deploy.
  • Run the shared C++ detection tests after changing core algorithms.
  • Verify first boot, provisioning, reconnect, and recovery on physical hardware.
  • Measure motion behavior in the intended room, not only on the bench.

Current commands, configuration fields, and frontend-specific constraints are maintained in the repository setup reference.
