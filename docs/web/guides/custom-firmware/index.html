Prepare the workspace

  1. Clone the repository

    Work from the repository root so the wrapper can locate shared code, frontend configuration, and tests.

  2. Install the project environment

    Create the repository virtual environment and install the declared requirements for the workflows you plan to use.

  3. Check ESP-IDF

    Native, Matter, and Streamer require a usable ESP-IDF installation. Run the doctor command before the first build.

./espectre doctor
./espectre <frontend> --help

Build and flash

Choose the target chip explicitly. Use each frontend's help output for current options and port naming.

./espectre esphome build --chip c3
./espectre native build --chip c3
./espectre matter build --chip c3
./espectre streamer build --chip c3 --clean
Streamer credentials are supplied at build time and Streamer binaries are not published by the browser flasher. Never commit local Wi-Fi or MQTT secrets.

Where to customize

Core

CSI formats, signal conditioning, features, and detectors. Keep C++ and Python algorithm behavior aligned.

Runtime

Platform-neutral orchestration and ESP-IDF services for capture, transport, storage, and lifecycle.

Frontend

Home Assistant, Matter, MQTT, BLE, and streamer-facing behavior belongs in the selected frontend.

Embed ESPectre in an existing firmware

The reusable C++ layers let an ESP-IDF product own boot, networking, storage, OTA, and UI while ESPectre supplies the sensing path.

  1. Connect CSI capture

    Feed compatible ESP32 CSI frames into the shared capture and processing boundary.

  2. Select the reusable layers

    Use the core directly for the smallest integration, or reuse runtime services when you also want lifecycle and orchestration.

  3. Map product events

    Translate movement score, motion state, calibration state, and diagnostics into the product's existing event system.

  4. Validate in context

    Measure CPU, memory, packet flow, reconnect behavior, and detection quality inside the complete product firmware.

ESPectre currently exposes reusable source layers rather than a precompiled binary SDK. It is GPLv3 software, so evaluate the license obligations before combining and distributing it with closed-source firmware.

Validate before deployment

  • Build the exact chip and frontend combination you will ship.
  • Run shared C++ detection tests after changing core algorithms.
  • Verify first boot, provisioning, reconnect, and recovery on physical hardware.
  • Measure motion behavior in the intended room rather than relying only on bench tests.
